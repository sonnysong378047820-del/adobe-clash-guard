# Adobe / Clash 双向启动检查器 — 2.1.1（文件夹版）

## 两边都检查

- Clash 界面或代理内核运行 → 从受管 Adobe 图标启动时弹窗并阻止；退出 Clash 后重试。
- Adobe 应用运行 → 从受管 Clash 图标启动时弹窗并阻止；保存工作、退出 Adobe 后重试。
- 两种弹窗均可取消，不启动目标。工具不会帮用户强关 Adobe 或 Clash，不会丢弃未保存工作。
- 已接入的新版图标通过同一启动互斥锁串行检查，减少几乎同时点击时的竞争；启动后最多短暂等待 8 秒确认进程可见，然后退出。不是长期后台监控。

## 重要：不是系统级绝对互斥

只能约束接入本工具的桌面快捷方式。Clash 自启动、开始菜单/任务栏原图标、直接运行 EXE、其他程序调用、重启后恢复应用、双击 PSD/JPG 文件关联等均可能绕过。工具不会修改这些入口、服务、注册表或开机设置。

要按受管图标实现日常双向提醒，需要自己关闭 Clash 的开机自启动，并只使用接入的 Adobe 和 Clash 图标。没有 Clash 桌面图标时，先手动创建它，再运行安装器自动识别；不支持只从托盘/自启动使用而要求拦截。

互斥锁是同一登录会话内的启动序列锁，不长期持有应用生命周期锁。进程权限、软件延迟子进程启动、多个用户会话、旧版入口、重名进程仍是边界，不保证任何情况下不能共存。严禁把本工具宣传成"全系统绝对互斥"或"保证解决 Adobe 网络问题"。

## 这个包是文件夹版

解压后的结构：

```text
AdobeClashGuard_v2.1.1\
  AdobeClashGuard\            <- 程序文件夹
    AdobeClashGuard.exe
    _internal\                <- 必须和 exe 放在一起
  使用说明.md / 使用说明.html
  重建说明.md
  licenses\  source\
```

**`AdobeClashGuard.exe` 不能单独拷出来用，也不能只发这一个文件。** 它需要同目录的 `_internal` 文件夹；两者一起移动、一起解压才正常。要发给别人，直接发整个 ZIP。

### 为什么用文件夹版

2.1.0 是单文件版，运行时先把自己解压到 `%TEMP%\_MEIxxxxxx`，退出时再删除。若安全软件（如腾讯电脑管家实时防护）正在扫描其中某个 DLL，删除会失败并弹出 `Failed to remove temporary directory` 警告。该警告无害，但容易让人误解。

2.1.1 改成文件夹版后不再向临时目录解压，**这个警告不会再出现**，启动也更快。代价是分发物从单个 exe 变成一个文件夹（仍以 ZIP 压缩包形式交付）。

## 首次运行可能被系统拦截

程序没有代码签名证书，Windows 或安全软件对首次运行作出提示是正常现象，**不是程序损坏，也不需要为此关闭安全软件**。

| 现象 | 处理 |
|---|---|
| 蓝色窗口"Windows 已保护你的电脑" | 点「更多信息」→「仍要运行」 |
| 安全软件提示"未知程序 / 风险程序" | 选择允许运行或加入信任；不要关闭实时防护 |
| 提示需要更高权限 | 用**当前同一个账户**右键「以管理员身份运行」 |
| 提示"另一个安装窗口已打开" | 先关掉已打开的检查器弹窗，再重试 |
| 安全软件隔离了程序 | 从隔离区还原并加入信任，再重新解压一次 |

公共桌面（`C:\Users\Public\Desktop`）上的 Clash 图标通常需要管理员权限才能修改，因此首次运行建议直接用"以管理员身份运行"。不要换成别人的管理员账户，也不要使用来源不明的"免杀/破解"版程序。

## 自动识别与安装

1. Windows 10/11 x64 用户完整解压分享包，双击 `AdobeClashGuard\AdobeClashGuard.exe`（首次建议右键以管理员身份运行）；无需安装 Python 或任何运行环境。
2. 自动只读扫描当前用户桌面、公共桌面顶层 `.lnk`；不全盘搜索、不进入桌面子目录。
3. Adobe 按目标 EXE 厂商版本信息，或 Adobe 路径＋已知应用文件名识别。Clash 按已知直接 EXE 名称识别。厂商信息只用于识别，不是签名认证。
4. 自动选中所有识别到的新 Adobe 和 Clash 入口，列出完整路径统一确认；每批最多 10 个。先备份并校验后才修改图标；首个失败就停。
5. 保留原名称、图标、参数、工作目录、窗口状态和管理员标记。拖入文件安全追加参数，不使用命令行外壳。
6. 看到"接入成功，并已校验"后，用原图标验证两种提示。只关闭 Clash 主窗口不算退出。

固定安装目录：`%LOCALAPPDATA%\AdobeClashGuard\v2.1`（目录名自 2.1 起保持不变，用于让已接入的图标自动沿用更新后的程序）；备份在其 `backups`，状态在 `state.json`。安装成功后解压目录不是运行依赖，可以移走；固定安装目录不能删除、也不能只移动里面的 exe。

Clash 的安装服务、Adobe IPC/更新后台服务不会单独作为反向拦截对象。反向检查覆盖主要 Adobe 应用进程，并加入已登记的其他 Adobe EXE 名称；未知且未登记的软件、改名进程可能漏检。Creative Cloud 应用本身属于 Adobe 应用，会阻止 Clash；需从托盘退出它，不需停止系统服务。

## 更新与升级

- **直接运行新版文件夹里的 `AdobeClashGuard.exe` 即为升级**：它会把固定安装目录里的程序替换为 2.1.1，并保留一个 `AdobeClashGuard.previous.exe` 作为回滚副本。
- **已接入的图标不需要重新接入**：它们指向固定的 `AdobeClashGuard.exe`，程序更新后自动使用新版。
- 升级前请先关闭正在运行的检查器窗口（含其他 Adobe/Clash 启动检查弹窗），否则程序文件被占用，安装器会明确提示。
- 若桌面上没有需要新接入的图标，程序会提示"检查器已更新"并直接完成，不会修改任何快捷方式。
- Clash 或 Adobe 自身更新后若换了安装路径、快捷方式或进程名：新版不会自动跟随，需先恢复原图标、取得新的正确快捷方式，再重新接入。

## 从旧版升级（1.x / 2.0 单文件版）

旧版是单文件打包，只有单向检查（Clash 拦 Adobe）。新版**会跳过**已接入旧版的图标，既不会自动升级它们，也不会覆盖旧程序目录。

想把它们统一到新版：先用旧版自带的恢复入口把图标还原成原始快捷方式，再运行本安装器重新接入。每一步都要确认路径、备份与校验，不要直接删除旧程序目录。

## 恢复

- **恢复原图标**：Win+R 输入 `%LOCALAPPDATA%\AdobeClashGuard\v2.1` 回车，运行"恢复 Adobe 与 Clash 原图标.lnk"。逐批确认后先备份当前受管图标，再恢复原文件；被其他程序改动过的图标不会被覆盖，备份与程序都不会删除。
- **程序回滚**：固定安装目录内的 `AdobeClashGuard.previous.exe` 就是升级前的上一版程序。
- 恢复不依赖解压目录，也不依赖当初从哪个 ZIP 安装。
