# 2.2.1 重建说明（文件夹版）

本文件说明如何从源码重建 AdobeClashGuard，以及如何替换第三方依赖与运行测试。项目以 GNU GPL-3.0 发布（见根目录 `LICENSE`）；随附的第三方文件分别遵守各自许可。

## 文件

| 路径 | 说明 |
|---|---|
| `src/adobe_clash_guard.py` | 应用逻辑（全部功能在此单文件内） |
| `tests/test_universal.py` | 38 项自动测试 |
| `tools/verify_package.py` | 端到端验收脚本（需打包产物就绪后运行） |
| `AdobeClashGuard.spec` | PyInstaller 打包配置（onedir） |
| `requirements.txt` | 构建依赖版本 |
| `licenses/` | pylnk3 LGPLv3、GPLv3、Python 许可、PyInstaller 许可与例外文本 |

`verify_package.py` 中"已接入图标数量"的断言只是开发机上的验收条件，不是产品安装要求。

## 环境与构建

Windows x64，Python 3.13。建议使用独立虚拟环境，命令在仓库根目录运行：

```text
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean AdobeClashGuard.spec
```

产物在 `dist/AdobeClashGuard/`，包含 `AdobeClashGuard.exe` 与 `_internal/`。

**`--onedir` 自 2.1.1 起是关键**：产出一个文件夹，运行时不再向 `%TEMP%` 自解压，因此不会出现"无法删除临时目录"的提示。若改回 `--onefile`，该提示可能再次出现（安全软件扫描 DLL 时删除失败），且安装器会把 `bundle_root()` 判为空、只复制单个 exe。

## 替换 pylnk3

pylnk3 以 LGPLv3 授权，你有权替换它。两种方式：

```text
# 方式一：装一个接口兼容的替代库
.venv\Scripts\python.exe -m pip install <你的 pylnk3 分支> --force-reinstall
```

方式二：把修改后的 `pylnk3.py` 放进 `src/`，它会优先于 site-packages 中的版本被导入。

只重建程序**不需要**把库装进全局环境，也不要替换或删除系统 Python。

## 测试

自动测试（38 项，使用工作区模拟目录，不会动真实桌面图标），在仓库根目录运行：

```text
.venv\Scripts\python.exe tests\test_universal.py
```

测试文件通过 `import adobe_clash_guard` 引用源码，运行前需让 `src/` 在 `sys.path` 上，例如：

```text
set PYTHONPATH=%CD%\src
.venv\Scripts\python.exe tests\test_universal.py
```

`verify_package.py` 需在程序文件夹构建完成后、且当前工作目录可写时运行。它会：

- 用打包后的 exe 做只读扫描；
- 在沙箱 `LOCALAPPDATA` 里真实执行一次 `--install`，验证程序文件夹复制到固定路径、旧版本被替换并保留回滚副本、`_internal` 更新、辅助入口生成；
- 验证两个方向的原生提醒与取消、启动锁、模拟安装与恢复的字节一致性；
- 对照真实桌面快捷方式哈希，确认未被修改。

正向（Clash 拦 Adobe）弹窗需要存在 Clash 或代理内核进程；测试机上 Clash 未运行时，脚本会释放一个改名为 `clash-verge.exe` 的 `PING.EXE` 作为同名阻塞进程，测试结束后立即结束它——不启动也不关闭用户真实的 Clash。

脚本内的弹窗关闭统一走"先发按钮消息、失败再发 `WM_CLOSE`"，等价于点击取消，因此测试永远不会误点"接入/恢复"。

注意各弹窗的按钮 ID 并不相同：提示框（`MB_OK`）用 `IDOK=1`，而"确认接入 / 恢复"是 `MB_YESNO`，取消它要用 `IDNO=7` 而不是 `IDCANCEL=2`——用错 ID 时消息框不匹配任何按钮，窗口不会关闭，脚本会一直等到超时。2.2.0 起扫描范围包含开始菜单，测试机上通常存在待接入的开始菜单入口，因此这条路径必然会被走到。临时工作目录由系统 `%TEMP%` 托管；若受环境删除策略影响未能自动清理，脚本会保留目录而不报错（`ignore_cleanup_errors`），人工清理即可。

若以开发解释器运行程序的 `--install`，程序会拒绝实际安装（未打包状态），正式安装只使用打包后的 EXE。
